# 方案对比

对任意技术方案进行结构化对比分析，帮助用户做出明智决策。

## 触发场景

- 技术选型：框架、库、语言、数据库等
- 架构设计：微服务 vs 单体、同步 vs 异步等
- 代码实现：不同算法、设计模式、数据结构的取舍
- 工具选择：CI/CD、部署方案、测试框架等
- 设计方案：UI 布局、交互模式、系统设计等

## 对比流程

### 第一步：明确对比目标

从用户问题中提取：

1. **候选方案**：列出所有待对比方案（至少 2 个）
2. **决策背景**：项目规模、团队能力、时间约束、已有技术栈
3. **核心关切**：用户最在意什么（性能？成本？可维护性？学习曲线？）

如果信息不足，主动追问：
- "你的项目规模和团队情况是怎样的？"
- "有没有已确定的技术约束？"
- "你最看重哪些方面？"

### 第二步：确定评估维度

根据对比类型选择合适的维度。以下为常见维度池，按需选取 **5-8 个**最相关的：

| 类别 | 可选维度 |
|------|---------|
| 技术 | 性能、可扩展性、可靠性、安全性、兼容性 |
| 工程 | 学习曲线、开发效率、可维护性、可测试性、调试难度 |
| 生态 | 社区活跃度、文档质量、第三方集成、长期维护前景 |
| 商业 | 开发成本、运维成本、许可证、人才市场 |

### 第三步：逐维度分析

对每个维度，为每个方案给出：
- **事实依据**（benchmark 数据、官方文档、真实案例）
- **相对评价**（优 / 良 / 中 / 差，或具体评分）
- **关键差异说明**（一句话点明核心区别）

### 第四步：输出对比报告

根据方案数量和复杂度灵活选择格式：

**简单对比（2-3 方案，≤5 维度）** → 直接用表格

**复杂对比（≥3 方案或 ≥6 维度）** → 表格 + 分项分析

**深度技术对比** → 表格 + 分项分析 + 代码示例

## 输出模板

### 表格对比

```markdown
## [对比主题]

| 维度 | 方案 A | 方案 B | 方案 C |
|------|--------|--------|--------|
| 维度1 | ★★★★☆ 说明 | ★★★☆☆ 说明 | ★★★★★ 说明 |
| 维度2 | ... | ... | ... |
```

### 分项分析（用于需要展开的维度）

```markdown
### [维度名称]

**方案 A**：[1-2 句核心优势/劣势 + 依据]

**方案 B**：[1-2 句核心优势/劣势 + 依据]

**小结**：[该维度下的最佳选择及原因]
```

### 结论

```markdown
## 结论

**推荐方案**：[方案名]

**推荐理由**：[2-3 句，紧扣用户核心关切]

**适用条件**：[该推荐成立的前提]

**注意事项**：[选择该方案需要额外关注的风险]
```

如果没有明显胜出者，给出**条件化推荐**：

```markdown
## 结论

- 如果 [条件 A] → 推荐 **方案 X**，因为 [原因]
- 如果 [条件 B] → 推荐 **方案 Y**，因为 [原因]
```

## 原则

1. **客观公正**：不带偏见，用事实和数据说话。如果某方案在特定场景下更优，明确指出场景。
2. **避免大而全**：只选最相关的维度，不为了"全面"堆砌无关维度。
3. **给出结论**：对比不是目的，帮用户做决策才是。必须给出推荐或条件化推荐。
4. **承认不确定**：如果缺乏足够信息做判断，坦诚说明而非强行下结论。
5. **贴合实际**：优先考虑用户的具体约束，不做脱离实际的理论分析。
